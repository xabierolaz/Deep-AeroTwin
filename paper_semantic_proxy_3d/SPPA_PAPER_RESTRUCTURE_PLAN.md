# SPPA paper restructure plan

This note records the current editorial decision after the July 2026 claim audit.

## Current diagnosis

The main manuscript is close to the right shape: a runtime-contract paper with
preliminary evidence. The 38-page technical supplement/artifact log is too large for a normal
submission package. It mixes specification, old prototype history, benchmark
tables, negative controls, planned work, and implementation diary material.

The supplement grew because it preserved every evidence boundary while the
implementation was moving quickly. That was useful for internal honesty, but it
now weakens the paper by making SPPA look less mature and more like a running
technical log.

## Submission shape

Recommended shape:

- one unified main paper, slightly expanded where needed;
- no 38-page formal supplement in the first submission;
- benchmark artifacts, logs, scripts, and long tables in an archived artifact
  package or repository;
- a short appendix only if the target journal explicitly allows it.

The current precheck artifact is `SUBMISSION_PRECHECK.md`. It should remain the
submission gate: the main runtime-contract version may proceed only with the
claim boundaries intact, while any full-experimental-paper claim remains blocked
until the four gates below are complete.

The supplement decision is now generated by `SUPPLEMENT_TRIAGE.md` from
`tools/sppa_sota_benchmark/audit_supplement_scope.py`. The triage reports 38
PDF pages, 2,402 TeX lines, and the decision
`do_not_submit_current_38_page_file`. Its preferred shape is
`main_paper_plus_short_artifact_index`: keep the main manuscript self-contained,
archive long benchmark/log material as artifacts, and create only a short
appendix if a target journal explicitly requires one.

Keep in the main paper:

- the SPPA descriptor/update contract;
- the operational representation policy;
- the semantic part decomposition figure;
- the input-aligned generator stress figure, clearly marked as not a SOTA
  ranking;
- one selected Unreal evidence table;
- one compact limitations/claim-boundary section.

Move out of the paper body:

- smoke-test diary sections;
- repeated HISM build/rebuild history;
- long HTTP replay tables;
- old OBJ prototype tables unless needed as a small historical sanity check;
- unresolved dependency/setup notes except as artifact metadata;
- planned evaluation matrices that read like a backlog.

## SOTA comparison decision

The old visual grid must not be described as a SOTA ranking. It is now an
input-aligned local audit with a first row labeled `Proxy input (not GT)` and
showing the crop/proxy input used by image-conditioned methods. That first row
is not ground truth.

A real SOTA ranking requires:

- recorded detection crops or a public reference image set;
- a dual-input protocol separating YOLO-detected image inputs from tag/text-only
  inputs;
- segmentation masks/bounding boxes when SPPA is evaluated from detections;
- target meshes, annotated footprints, or human-preference scores;
- a contemporary method set including TRELLIS.2, Hunyuan3D 2.1, SF3D, TripoSR,
  and any method that the target venue would expect;
- explicit metrics rather than a visual grid alone.

SPPA should not be ranked as an image-to-3D asset generator. In that study, SPPA
is the semantic-runtime proxy baseline: label/bbox/mask/pose in, bounded
primitive actor out.

The current dual-input readiness report is
`benchmarks/results/sota_dual_input_readiness.md`. It explicitly blocks a SOTA
claim because the current real probes have four manually reviewed ROIs but zero
target-compatible YOLO detections in those ROIs. The tag/text track is also
incomplete until text baselines are rerun on the same reviewed tags.

## Detection/ground-truth row decision

Yes, the comparison should have a first row showing the input evidence. For a
submission-ready figure, that row should be recorded detections: crop, bbox,
mask/footprint, class label, confidence, and pose/scale evidence where available.

Do not call that row ground truth unless it is annotated or comes from a public
benchmark with target geometry. A detector crop is input evidence; a manually
annotated mask/footprint or reference mesh is ground truth. The current decision
is recorded in `FIRST_ROW_GT_DECISION.md`.

Current state: `experiments/sppa_detection_reference/20260703_synthetic_yolo`
contains a synthetic YOLO reference manifest with three 2D bbox ground-truth
items (`biker`, `cow`, `tower`), but zero readable crop images. It upgrades the
detection-derived gate from missing to partial only. It must not replace the
first visual-grid row or be described as real detector/flight evidence.

The SPPA row in `sppa_input_alignment_six_case_visual_grid.png` is regenerated
with configurable low-alpha face edges in `render_mesh_views.py`. This is a
presentation fix only: it reduces the false impression of wireframe/internal
geometry crossing the mesh while preserving the same OBJ geometry and material
manifests. The visual/material audit now checks this renderer contract.

## Truck visual decision

Use the language-to-parts-to-3D figure as the main figure. It already includes
the short/long truck contrast and explains the core idea.

Keep the standalone truck role-preservation image as supporting evidence only.
It is clearer as a diagnostic, but it is too narrow to be the main visual
argument. Do not include both as full figures in the body unless the paper is
rewritten around role-preserving parametric adaptation.

This decision is now checked by `TRUCK_FIGURE_DECISION.md`, generated from
`tools/sppa_sota_benchmark/audit_truck_figure_decision.py`. The audit verifies
that the main manuscript includes `sppa_language_to_parts_to_3d_v17.png` once,
does not include `sppa_truck_role_adaptation.png`, and that the short/long truck
part-invariance metrics pass: cab and tire scale deltas stay at 0.0, cargo
length increases by 2.925 m, and tire count changes from 6 to 8.

## Minimum gates before claiming a full experimental paper

1. Common representation benchmark: boxes, billboards, curated assets, SPPA
   actor, SPPA HISM, and selected image-to-3D methods under a shared protocol.
2. Detection-derived evidence: real or simulated UAV detections with crops,
   masks/footprints, bbox, yaw, and scale/pose metadata; report failure cases.
3. Phase-aligned Unreal profiling: GameThread, RenderThread, GPU, draw calls,
   hitches, memory, actor/component counts, and backend/phase labels.
4. Flight-derived or simulated scheduler rates: create, pose-change,
   shape-change, and class-change rates per active track, then rerun the HISM
   partial-update benchmark with those rates.

Operator/user evidence remains required before claiming pilot readability,
workload reduction, situation-awareness benefit, or operational risk reduction.
