# SPPA-MVFit preregistration-style protocol

Protocol frozen: 2026-07-15, before generating or inspecting the new held-out
benchmark results.

Status: internal prospective protocol for the redesigned SPPA study. This is
not a registered report and was not deposited with an external registry. Any
post-freeze deviation must be appended to the deviation log; the original text
must not be silently rewritten.

## 1. Scientific question and single contribution

Can calibrated top- and side-view binary silhouettes improve the 3D occupancy
of a lightweight semantic primitive actor, relative to the same actor generated
from the semantic family alone, when both modes use one shared generator?

The sole proposed contribution is **SPPA-MVFit**: a class-agnostic optimizer
that adjusts a bounded parameter vector of the existing semantic primitive
actor by minimizing silhouette disagreement. Semantic families define only the
frozen part graph and default priors. The optimization rule, objective,
parameter bounds, stopping rule, and uncertainty outputs are shared across all
families. Text-only and text-plus-silhouette modes must call the same actor
generator. No class-specific post-processing, mesh editing, or legacy actor is
permitted.

This protocol does not test universal text-to-3D, image-to-3D reconstruction,
detector accuracy, flight performance, operator utility, safety, or SOTA
ranking. The four user-supplied real images remain qualitative failure probes;
their camera and metric data are declared replay assumptions and they have no
3D ground truth.

## 2. Hypotheses

### H1: primary geometry hypothesis

On the held-out synthetic test actors, SPPA-MVFit will improve case-level 3D
occupancy IoU over `sppa_text_only`, the same generator evaluated at its frozen
semantic-family defaults.

Primary endpoint: the mean paired difference

`mean(case_mean_voxel_iou_sppa_mvfit - case_mean_voxel_iou_sppa_text_only)`.

The analysis unit is a source actor. Each actor's five observation conditions
are averaged before any population statistic is computed. H1 passes only when
the two-sided 95% actor-level bootstrap confidence interval for the paired mean
difference has a lower bound of at least +0.030 absolute IoU. A positive point
estimate with a lower bound below +0.030 is not a pass.

### H2: secondary representation hypothesis

SPPA-MVFit will exceed the strongest non-oracle lightweight baseline on
case-level mean voxel IoU. This is secondary and cannot rescue a failed H1.
The comparator is selected mechanically as the baseline with the highest test
mean among `bbox`, `ellipsoid`, `capsule`, `billboard`, and
`nonsemantic_visual_hull`. The paired bootstrap interval is reported without
turning this data-dependent comparison into a primary confirmatory test.

### H3: bounded-cost hypothesis

On the benchmark machine, after five warm-up calls, SPPA-MVFit will have median
CPU wall time below 100 ms and p95 below 250 ms on the prespecified timing
subset. Raw per-call samples are retained. H3 is a local implementation result,
not an Unreal, embedded, network, or flight latency claim.

## 3. Source actors and independence boundary

Ground-truth actors are generated by `generate_source_actors.py`, an independent
synthetic source generator whose primitives, parameter distributions, and
random seeds are frozen in the release. Source actors are unions of geometric
solids sampled in metric coordinates. SPPA-MVFit does not receive the source
primitive list, the ground-truth occupancy, source parameters, or evaluation
views.

The six morphology families are:

1. compact vehicle;
2. articulated vehicle;
3. quadruped;
4. branching vertical object;
5. lattice/tower object;
6. rider-cycle assembly.

These labels identify synthetic morphology families only. They are not claims
about real cows, vehicles, towers, trees, or cyclists. Source-generator code is
kept separate from the SPPA generator so that evaluation is not projection
inversion of the same geometry function.

The benchmark contains:

- development split: 144 actors, 24 per family, seeds 110000--110143;
- held-out test split: 240 actors, 40 per family, seeds 210000--210239;
- five observation conditions per actor: clean plus four deterministic mask
  perturbations generated from actor-specific seeds;
- primary analysis units: 240 test actors, not 1,200 correlated observations.

The test manifest and raw observations are generated and hashed before the
test command is run. Development results may be used to debug and choose fixed
optimizer constants. Test aggregate results may be computed once after the
method code hash is recorded. Re-running because the result is unfavorable is
forbidden. Necessary reruns caused by a documented software failure must retain
the failed output and be entered in the deviation log.

This is developer-held-out synthetic data, not an externally blinded or public
real-world test set. The manuscript must say so.

## 4. Observation contract

Every method receives the same case identifier, morphology-family token,
metric calibration, and two 96x96 binary silhouettes:

- orthographic top view;
- orthographic side view.

No method receives RGB pixels, detector labels/confidence, source parameters,
ground-truth occupancy, the evaluation projections, or real/replay telemetry.
The semantic-only baseline ignores the silhouettes by definition. Baselines
that cannot consume a family token may ignore it; they are not given additional
information.

Five observation conditions are frozen:

1. clean masks;
2. mild boundary erosion/dilation;
3. moderate boundary erosion/dilation;
4. partial occlusion;
5. salt-and-pepper mask corruption plus one small false component.

The perturbation family and magnitude are stored per row. No failed or visually
unattractive case is excluded.

## 5. Representations under comparison

All baselines are generated locally from the frozen observation contract.
They are not literature-reported numbers.

- `bbox`: calibrated axis-aligned box from observed silhouette extents;
- `ellipsoid`: one calibrated ellipsoid fitted to the same extents;
- `capsule`: a calibrated main-axis capsule fitted to the same extents;
- `billboard`: crossed thin planes carrying the two silhouette envelopes;
- `nonsemantic_visual_hull`: voxel intersection of the two silhouette
  extrusions, with no family input;
- `curated_family_template`: frozen low-poly family template selected only by
  the declared family token; this is the available curated-asset baseline;
- `sppa_text_only`: shared SPPA generator with the same frozen family template
  and default parameter vector;
- `sppa_mvfit`: the same generator and part graph after the generic bounded
  silhouette optimizer.

If `curated_family_template` and `sppa_text_only` are byte-identical in the
implementation, both names must not be plotted as independent evidence. The
result table will keep one row and record the alias explicitly.

The circular `sppa_task_fit_ranking` and its 6/6 versus 0/6 output are excluded
from every redesigned result, figure, abstract, and conclusion.

## 6. Metrics

### Primary metric

Three-dimensional voxel IoU on a common 64x64x64 metric grid covering the
source actor's evaluation volume. GT occupancy comes only from the independent
source generator. Predicted occupancy is rasterized from each representation.

### Secondary geometry metrics

- BEV occupancy IoU;
- mean silhouette IoU over four evaluation views not provided as inputs;
- normalized symmetric Chamfer distance between occupied-surface samples;
- relative occupied-volume error;
- containment error (GT outside prediction and prediction outside GT);
- failure rate, where voxel IoU is below 0.25;
- robustness loss from clean to each perturbed observation condition.

Metrics are reported per family and in aggregate. The aggregate gives each
actor equal weight. No family, seed, perturbation, or metric may be removed
after test inspection.

### Cost metrics

- raw CPU wall time per inference call;
- primitive count;
- deterministic triangle-equivalent count under the frozen tessellation rule;
- serialized descriptor bytes.

Cost and geometry are reported separately. They are not collapsed into a
manually weighted score or ordinal ranking.

## 7. Repetitions, seeds, and statistical analysis

- Dataset seeds are fixed above and expanded in the manifest.
- Optimizer tie-breaking and any stochastic search use seed 57057 plus the case
  index; the result must be deterministic for a given case.
- Each actor has five observation conditions, averaged to one case-level value.
- Timing uses a stratified subset of 60 test actors (10 per family), all five
  conditions, 5 warm-up calls followed by 20 recorded calls per method/case.
- Confidence intervals use 10,000 stratified actor-level bootstrap resamples,
  seed 77157, preserving family counts.
- Family-specific secondary comparisons use Holm correction at alpha 0.05.
- Exact sample counts, missing values, exceptions, and non-finite values are
  reported. Exceptions score as failures; they are not silently dropped.

No frame from a single Unreal run is treated as an independent scientific
replicate. Historical timing summaries are not substituted for these raw
samples.

## 8. Exclusions and stopping rules

There are no data-dependent exclusions. A case is excluded only if its frozen
input or GT hash fails before any method runs; the whole release is then invalid
until the provenance defect is repaired. Algorithm exceptions remain in the
raw table with failure metrics.

Development stops before test execution when all of the following hold:

1. protocol, dataset generator, observation schema, metric code, baselines, and
   optimizer are versioned;
2. development tests and contract tests pass;
3. test-input and GT hashes are frozen;
4. method and environment hashes are recorded;
5. a test command is emitted to an append-only run log.

After the first valid test execution, optimizer constants, template parameters,
and primary analysis code are frozen. Corrections to analysis bugs require a
deviation entry, the original output, a minimal regression test, and reporting
both pre- and post-correction hashes.

## 9. Falsification and allowed conclusions

The central scientific claim is falsified if H1 fails. In that event the paper
may report a negative benchmark result or revert to a narrowly scoped artifact
paper, but it must not claim that visual evidence improves SPPA geometry.

Even if H1--H3 pass, the strongest allowed conclusion is that bounded
multiview silhouette fitting improves occupancy for these six synthetic
morphology families under the frozen calibrated observation contract. Passing
does not establish real-world detector robustness, universal correctness,
operator utility, safety, or superiority to neural 3D reconstruction.

## 10. Provenance states

Every row and artifact uses exactly one primary provenance label:

- `synthetic_geometry`: generated source actor, mask, GT, or derived benchmark;
- `real_image`: an externally supplied image whose pixels are not generated by
  this pipeline, with origin/license limitations recorded;
- `declared_replay`: assumed camera, pose, scale, or telemetry used to exercise
  a contract without measured flight;
- `measured_flight`: reserved for independently recorded flight data; no such
  data are present in this study.

Derived files retain the provenance of their source and list every source hash.
No declared replay may be relabeled as measured flight.
